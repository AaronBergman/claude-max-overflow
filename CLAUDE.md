# claude-max-overflow — repo notes for Claude

Public tool (github.com/AaronBergman/claude-max-overflow, MIT, EXPERIMENTAL): route Claude Code usage across multiple Claude Max subscriptions. One **primary** account (`~/.claude`) owns all config; **overflow** accounts are isolated `CLAUDE_CONFIG_DIR` profiles that symlink back to the primary, so settings/skills/history/memory are shared and `--resume` works across accounts. `claude` becomes a shell function that picks the account with headroom at launch, keeps overflow credentials alive, re-logs-in dead ones, and mirrors overflow sessions into the primary's claude.ai.

Relies on undocumented Claude Code internals (OAuth in the OS credential store, the `/api/oauth/usage` endpoint, hook events, transcript layout). Any Claude Code update can break it. Target platform: macOS + zsh (Linux/bash best-effort).

## Files
- `claude-overflow.sh` — the whole loader (sourced from the user's shell rc). Everything lives here: config vars at top, `_cof_*` helpers, and the public functions `claude` / `cacct` / `cswap` / `climits` / `claude-overflow`.
- `cof-insession-hook.sh` — the in-session switch hook (`Stop` + `StopFailure`), injected into managed sessions via `--settings`. Inert unless `COF_MANAGED=1`.
- `cof-dashboard.py` + `cof-dashboard.html` — `claude-overflow dashboard` / `claude_router`: stdlib-Python localhost server (port 8787, background, idle-exits after 45 min) + single-page vanilla-JS/SVG dashboard. Read-only replica of `_cof_cred_of`/`_cof_pick` in Python (never rewrites accounts.tsv); gets effective config by sourcing the loader in bash; renews stale tokens only via `_cof_ping`; sign-in via `_cof_login_bg`. Writes the same `cache/usage-<label>.json` as `_cof_fetch`. Keep its picker replica in sync when `_cof_pick` changes. Usage-endpoint etiquette (learned 2026-09-27): a dashboard tab left open overnight polling every 60 s made ~2,900 fetches in 24 h and got 429s on 3 accounts; a 429 also blinds the router (`_cof_pick` -> `usage-check-failed`, hook's proactive check exits). The dashboard now uses a 5-min TTL shared with the router's cache files, a 10-min per-account 429 backoff, and no polling while its tab is hidden. Keep new callers of `/api/oauth/usage` similarly frugal. Account management from the page: `POST /api/add {label,email}` validates (label regex, reserved `primary|login|all`, no duplicate label/email incl. primary), runs `_cof_add` with stdin closed (non-interactive, so it only registers), then `_cof_login_bg <label> dashboard force`; `POST /api/remove/<label>` only for signed-out overflow accounts (runs `claude-overflow remove`). `_cof_login` now back-fills an empty email in accounts.tsv with the account that actually signed in, and `_cof_add` reserves `login`/`all` (they'd collide with `_cof_pick`'s `login` sentinel and `login all`).
- `cof-context.py` + `cof-mcp.py` + `plugin/` + `.claude-plugin/marketplace.json` + `claude-on`: the **claude-router plugin** (2026-09-27), so every Claude Code session knows about the router.
  - `cof-context.py` is one hook script for SessionStart (the `<claude-router>` block: account, managed or not, all accounts' windows and resets, headroom, pick, warnings), UserPromptSubmit (silent unless the band 80/90/95 changes or the session is paused; cache-only) and PreToolUse `Agent|Task|Workflow` (capacity note at >= 60% for Workflow or background Agent, >= 85% for a foreground Agent; 20-min cooldown). It imports `cof-dashboard.py` for everything (accounts, creds, `fetch_usage(src="ctx")`, `simulate_pick`).
  - `cof-mcp.py` is a hand-rolled stdio MCP server (`router_status`, `router_hops`, `router_open_dashboard`) importing `cof-context.py`. Its `instructions` do reach the model's system prompt, and are truncated past roughly 2k chars, so keep them short.
  - Why a plugin rather than settings.json and `claude mcp add`: each overflow profile has its own `.claude.json`, so user-scope MCP servers don't reach them, whereas `~/.claude/plugins` and `settings.json` are symlinked into every profile.
  - The installed plugin is a copy in `~/.claude/plugins/cache/claude-max-overflow/claude-router/<ver>/`. Hooks and MCP call `~/.claude-overflow/cof-*.py` (copies from setup; symlink them to the repo for live edits). Manifest or skill edits need a version bump plus `claude plugin marketplace update claude-max-overflow && claude plugin update claude-router@claude-max-overflow`.
  - Which account a session is on comes from `CLAUDE_CONFIG_DIR`. "Managed" requires `COF_MANAGED=1`, a matching `COF_ACCOUNT`, and the pid in `COF_PIDFILE` being the **nearest `claude` ancestor**; that last check keeps a `claude -p` child of a managed session from inheriting "managed".
  - `COF_CTRL_DIR/paused` and `switch` are pre-created empty each leg, so only non-empty means paused.
  - 429 backoff is persisted in `cache/ctx/backoff-<label>` and shared with the dashboard. Credential states from full snapshots are kept in `cache/ctx/cred-states.json` for the cache-only hooks. Hook errors go to `cache/ctx/errors.log`, never to the session. Kill switch: `CLAUDE_ROUTER_CONTEXT=0`.
  - `claude-on <label> [args]` sources the loader in bash, clears `COF_*`, and runs `cacct`: the way to bill work to another account from inside a session (subagents always bill the session's account). In a stripped shell (the Bash tool snapshot), `cacct <overflow label>` now hands off to `claude-on` instead of silently running primary.
  - Verified 2026-09-27 with real headless sessions (`--plugin-dir` with faked 91% usage, then the installed plugin via `claude-on <overflow label>`): the SessionStart block, PreToolUse `additionalContext` (seen by the model before the tool runs), and the MCP tools on an overflow profile.
- `cof-statusline.py`: status-line segment (`acct:<label>[(fixed)] [fable:N%] pool:N% [next:<label>]`), cache-only, imports cof-context. Users call it from their own status-line script. Status-line wrappers can put several processes between claude and the script (one real setup: claude -> sh -> node -> sh -> bash -> python), which is why the managed check walks up to 8 ancestors. Stale logins (access tokens last ~8 h; the keep-alive runs every 12 h) are renewed on demand: when any snapshot finds one, a detached refresher runs `renew_login` (the loader's `_cof_ping`, so Claude Code refreshes under its own lock; at most every 30 min per account, logged to `cache/ctx/renew.log`) and then reads usage. Cache-only readers (status line, prompt hook) background-refresh this session's account after 5 min and the others after 15 min; a failed refresh waits 10 min (`refresh-<label>.lock` holds the retry-after epoch). Measured 2026-09-28 with several live sessions: at most ~11 usage fetches per account per hour, router included, and no 429s.
- `cof-restart.sh` + `commands/restart.md`: the `/restart` slash command (2026-10-10). The command runs the script as a `!` pre-command (`allowed-tools` covers it, `disable-model-invocation: true`), passing `${CLAUDE_SESSION_ID}` (fallback: `CLAUDE_CODE_SESSION_ID`, which Claude Code sets fresh for every child shell). The script reuses the switch protocol: writes `<COF_ACCOUNT>\n<sid>\nrestart` to `$COF_CTRL_DIR/switch` and SIGTERMs claude immediately (no flush delay: no turn is running). `_cof_run_managed` treats reason `restart` as a same-account relaunch (own message, no notification); it is never written to `insession.log`, so hop counts and the ping-pong check don't see it. Guards that change nothing and print `Not restarted: ...` (the model relays it): no transcript yet, not `COF_MANAGED`, `CLAUDE_PID` != the pid file (nested session), a switch already pending. `~/.claude/commands/restart.md` is a plain copy (setup installs it only if absent; uninstall removes it only if it mentions `cof-restart.sh`). Verified 2026-10-10 end to end in an isolated tmux session: same pid-file shell relaunched `--resume <sid> --permission-mode default`, the model recalled context from before the restart, and the transcript had no trace of `/restart`. Shells opened before a loader edit keep the old `_cof_run_managed` in memory until a new terminal.
- `claude-shim`: optional (setup offers it, default no) router-aware `claude` for programs, installed as `~/.claude-overflow/shim/claude`; the loader prepends that dir to PATH when the file exists. Loads the router and calls its `claude` function; `CLAUDE_OVERFLOW_SHIM=0` passes straight to the real binary. Line 2 carries the marker `claude-max-overflow-shim`, which `_cof_bin` and the shim's own `real_claude` skip. `COF_SHIM_ACTIVE` (set by the shim, cleared by every router launch) makes a re-entered shim exec the real binary instead of recursing. See "Binary resolution" below.
- `tests/test-bin-resolution.sh`: offline regression test (bash + zsh, fake binary padded past 64 KB, `security`/`curl`/`osascript` stubbed, per-case 20 s alarm). Run it after touching anything that launches Claude Code.
- `setup.sh` — guided installer (copies the runtime files to `~/.claude-overflow`, wires the rc line, adds accounts, offers keep-alive, the plugin, the `claude-on`/`claude_router` links and the claude-shim). Idempotent.
- `uninstall.sh` — removes keep-alive, plugin, links, shim, rc line; offers to log out overflow profiles (via the real binary) and to delete `~/.claude-overflow`. Never touches `~/.claude`.
- `README.md` — user-facing docs. Keep in sync with behavior changes.

For development, symlink the files in `~/.claude-overflow` to the repo instead of copying them, so editing the repo changes the live tool. Accounts: `~/.claude-overflow/accounts.tsv`. Machine-specific notes belong in `CLAUDE.local.md` (gitignored); this repo is public, so keep account labels, emails and home paths out of tracked files.

## In-session switching (the current feature)
A managed conversation moves itself to another account when the current one runs out mid-session, instead of just failing. Entry point: `cacct` routes interactive/persisted launches through `_cof_run_managed`, which injects the hook, records claude's pid (via `sh -c 'echo $$>pid; exec claude'`), and loops — on a `switch` control file it re-launches `--resume <session-id>` under the next account. The hook decides via `_cof_pick`, writes the target, and ends the session with a detached `SIGTERM`. If nothing has headroom it writes `paused` and leaves the session up. See README "Switching accounts mid-conversation".

Relaunches (hop or `/restart`) re-pass the launch flags that shape a session (permission flags, `--model`, `--effort`, `--add-dir`, `--mcp-config`/`--strict-mcp-config`, `--plugin-dir`, `--agent`, `--append-system-prompt`, `--chrome`/`--no-chrome`, `--ide`; `--add-dir`/`--mcp-config` are variadic, values run to the next flag) and drop session-picking flags and the prompt. Before 2026-10-10 only `--add-dir` survived, so a `cf` session came back in the default permission mode after a hop.

Key verified facts (2026-09-15): cross-account `--resume` restores full context in one transcript; SIGTERM exits an interactive session cleanly and preserves the transcript; `--settings` hooks **merge** with (don't replace) the user's global hooks; the exec-launcher's pid file holds claude's real pid.

## Automatic sign-in (2026-09-16)
A dead (signed-out) account gets its browser sign-in opened *for* the user whenever that could plausibly unlock usage; the user only completes the login. Four triggers: (1) a launch that needs the account now (`_cof_resolve` → `_cof_offer_login`, foreground, `CLAUDE_OVERFLOW_AUTOLOGIN=1` no longer prompts; `ask` restores the `[Y/n]`); (2) any interactive session launch (`cacct` → `_cof_login_dead_bg`, background, cooldown `CLAUDE_OVERFLOW_LOGIN_RETRY_HOURS`); (3) the in-session hook when only dead accounts are left (force, no cooldown; `paused` line 1 is `wall`|`proactive`; the worker gets `COF_LOGIN_CTRL`/`COF_LOGIN_SID` and on `wall` writes `switch` + SIGTERMs the session itself once the login lands); (4) the keep-alive when `_cof_user_present` (console user, unlocked, HID idle < 300 s). The background path is `_cof_login_bg` → `_cof_detach` (setsid via util-linux or perl POSIX, own session so it survives hooks/launchd; plist has `AbandonProcessGroup`) → `_cof_login_worker` (`_cof_login` with a `CLAUDE_OVERFLOW_LOGIN_TIMEOUT` bound because there is no tty; log `login.log`). Verified 2026-09-16: `claude auth login --email X` works with no tty (opens the browser via `open`, waits for the localhost callback, exits 124 on timeout, nothing left running); the hook's decisions surface via `{"systemMessage":…}` on stdout and `insession.log`.

Credential store: `_cof_cred_of <label>` is the only correct way to get an account's credential source. Claude Code may keep a profile's login in the Keychain (`Claude Code-credentials-<sha8(dir)>`) or in `<dir>/.credentials.json` and migrates between them; `_cof_cred_of` checks both and rewrites the `accounts.tsv` row in place (`_cof_put_row` preserves row order = overflow priority). Never `bash -x` the hook or loader: sourcing traces credential JSON into stderr.

`_cof_notify` escapes quotes/backslashes for AppleScript; before 2026-09-16 any title containing a quoted label silently produced no notification.

## Usage history (2026-09-25)
`_cof_fetch` calls `_cof_history`, which appends `{t,k,s,w,sc,sr,wr,x,src}` to `~/.claude-overflow/usage-history.jsonl` on every real network fetch (not cache hits). The dashboard appends too (`src:"dash"`) and additionally reads the target account's `session X% weekly Y%` recorded in `insession.log` hop lines. The file is unbounded; ~100 bytes per fetch.

Model-scoped windows (fixed 2026-09-26, found via the dashboard): the in-session hook hops when ANY window incl. `weekly_scoped` (e.g. Fable) is >= `INSESSION_AT`, or on a rate limit, but `_cof_pick` used to check only 5h + weekly for overflow accounts, so it could pick an account that was also out for that model -> ping-pong (2026-09-17/18: sessions bounced between two overflow accounts 16 and 18 times). Now `_cof_pick <exclude> scoped` also requires `sc < FULL_AT`; the hook passes `scoped` when sc >= INSESSION_AT (Stop) or when a `rate_limit` StopFailure arrives while the account's 5h and weekly are both < FULL_AT (fresh fetch); the launch pick sets it itself when only the primary's scoped window tripped. Reason strings then include `scoped N%`, and the no-headroom reason becomes `all accounts near limits (incl. the model-scoped window)` (the hook matches the prefix). The dashboard's Python picker mirrors this; its ping-pong check treats bursts before `PINGPONG_FIX` as history.

## Binary resolution (2026-10-17)
Nothing in the loader may run Claude Code through a PATH lookup of `claude` when it means a specific account: use `_cof_run_in <dir>` (or `"$_COF_BIN"` where `timeout`/`env` need an executable, after `[ -n "${_COF_BIN:-}" ] || _cof_bin >/dev/null`). `_cof_bin` walks `_cof_claude_paths` (`whence -pa` / `type -Pa`, PATH order), skips the shim marker, follows a small (< 64 KB) `#!` wrapper to the absolute `/…/claude` path it names, skips wrappers that name none, and accepts anything else (native binary, npm `cli.js`). Why: a `claude` earlier on PATH that re-enters the router re-picks the account and, for subcommands, forces primary, dropping `CLAUDE_CONFIG_DIR`. On 2026-10-16 that turned an overflow account's detached sign-in (`env CLAUDE_CONFIG_DIR=<overflow> claude auth login`) into a sign-in of the primary; the router even reported success because its email check read the overflow profile's `.claude.json`. Against the old loader the shim also recursed without bound. Also: `claude auth …` with a non-empty `CLAUDE_CONFIG_DIR` runs in that dir (every other subcommand stays on primary), so `CLAUDE_CONFIG_DIR=<dir> claude auth logout` (printed by `claude-overflow remove`) can't hit the primary. The stripped-shell `cacct` fallback hands every label, primary included, to `claude-on`. The only remaining PATH lookups are those stripped-shell fallbacks, where reaching the shim is the point.

## Conventions
- Everything is POSIX-ish sh in one file; must pass both `bash -n` and `zsh -n`. Public functions guard with `type _cof_run_in >/dev/null 2>&1 ||` so they degrade to plain primary when sourced into a stripped shell (e.g. Claude Code's Bash tool snapshot).
- Never rotate OAuth tokens outside Claude Code (its refresh uses a cross-process lock; external rotation → `invalid_grant` and a signed-out profile). Refreshes go through a 1-token `claude -p` ping (`_cof_ping`).
- `--bare` never reads OAuth; subcommands (`mcp|auth|config|rc|…`) run on primary (except `auth` with an explicit `CLAUDE_CONFIG_DIR`) and never get the in-session `--settings` injected (the CLI rejects it, e.g. `claude rc` -> "Unknown argument: --settings"). `_cof_is_subcommand` reads the list from `claude --help` (cached in `cache/subcommands`, keyed on every `claude` on PATH + mtime, re-parsed daily); `--help` omits hidden subcommands, so add those (and their aliases) to `_COF_SUBCMDS_HIDDEN`.
- Run `bash tests/test-bin-resolution.sh` after changing anything that launches Claude Code.
